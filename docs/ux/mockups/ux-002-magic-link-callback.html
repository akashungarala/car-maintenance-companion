UX-002 — Arriving from the sign-in link

Reference for docs/ux/ux-002-magic-link-callback.md. Two states only: it is working, or the link cannot be used.

Loading — the expected state, usually under a second

Signing you in…

No button. The exchange starts the moment the page loads, so a real visitor never acts — and a mail scanner, which only issues GETs, never spends the link.

Error — identical for every cause

⚠️

This link cannot be used

Sign-in links work once and expire after 15 minutes.

Request a new link

Why this screen looks like almost nothing

  • No success state. Success is being redirected to the garage. An interstitial saying "you're signed in!" is a screen whose only content is a delay.
  • No confirm button. A "click to sign in" page would defeat scanners too, at the cost of an extra deliberate click on every sign-in, forever. The POST already solves it.
  • One error for four causes. Expired, already used, never existed, altered — naming which would tell an attacker which tokens once existed, and none of them changes what the user does next.
  • Missing token is not a separate state. A bookmarked callback URL is the same dead end as an expired link, and two ways of saying so is one too many.
